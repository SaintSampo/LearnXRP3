BOTICON Concept D

Pit crew

A buddy for the hardware, not the code. It reads telemetry and logs, runs a checkup, and points at the part: "left motor never moved, check port 2". Talks like a race crew, fixes the half of classroom problems that are cables and batteries. From the working group's log-analyzer idea.

telemetry and logs onlyno student text neededworks for teachers too
BOTSVG
Pit crew · XRP-3F2A
Battery 7.9 V · firmware 2.1.0 · 30 s of telemetry
What it looks at
  • Did each motor move when asked?
  • Do the encoders count when wheels turn?
  • Do sensors change when the robot moves?
  • Battery, brownouts, resets
  • The last 50 shell lines
Says what it sees, then one thing to try. If that does not fix it, it asks the teacher to come over, with the checkup attached.
Press "Run a checkup". The robot will wiggle each wheel and read each sensor for three seconds.
Model input is structured: a JSON checkup, not free text. Cheap, fast, and the same for every student, so it is easy to test.Also the first thing a teacher opens when a robot "does nothing".

BOTICON Concept E

Teacher's copilot

Students never talk to an AI. The buddy sits with the teacher: it reads the room, groups students by what they are stuck on, drafts the next thing to say, and turns today's errors into tomorrow's warm-up. The safest concept for under-13 classes and the one that helps a first-year robotics teacher most.
